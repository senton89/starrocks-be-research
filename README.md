# starrocks-be-research

Исследование кодовой базы StarRocks Backend (BE, C++) версии 3.5.11: поиск закрытых бинарных зависимостей, сборка без них и разбор возникшего при запуске SIGSEGV.

**Статус:** исследование завершено; issue в upstream готовится.

## Что и зачем

Требовалось выяснить, есть ли в дереве исходников BE закрытые (не открытые) компоненты, можно ли собрать BE без них и что при этом ломается. Отдельный фокус — подсистема spill (сброс данных на диск при нехватке памяти): зависит ли она от закрытых библиотек. Работа выполнена по рекомендации преподавателя СПбГУТ, NDA нет.

## Главный результат

- **Найдена одна закрытая зависимость — StarCache** (`thirdparty/installed/starcache/`, `libstarcache.a`): 116 ссылок в 29 файлах. BE собран без неё флагом `--without-starcache` за 9 мин 3 с, ошибок компиляции нет.
- **Собранный BE падает на старте с SIGSEGV** до входа в `main()`: бесконечная рекурсия в `my_malloc` (`be/src/service/mem_hook.cpp:157`) через доступ к TLS из контекста динамического линкера, ~22 000 кадров стека. Предложен фикс — флаг повторного входа с прямым вызовом `je_malloc`.
- **Подсистема spill (`be/src/exec/spill/`, 28 файлов) не зависит ни от StarCache, ни от Starlet** — локальный spill-to-disk работает на чистом POSIX I/O.
